# 豆丁健身 - 微信小程序登录（v1）

> **版本**：v1.0.0  
> **更新时间**：2026-11-10  
> **服务**：`POST /api/auth/wechat-login`  
> **身份**：沿用已有 JWT。小程序只保存 token，请求头为 `Authorization: Bearer <token>`。

本文是微信登录这一阶段的行为说明。健身记录接口形状不变。`POST /api/auth/dev-login` 仍只给本地没有微信密钥时使用，不是正式登录。

## 用户路径

1. 打开微信小程序。启动时调用 `uni.login`（即 `wx.login`）拿到一次性 `code`。
2. 客户端把 `{ code }` 发给 `POST /api/auth/wechat-login`。
3. 服务端用环境变量里的 AppID、AppSecret 请求微信 `code2Session`，拿到 `openid`。
4. 在共用的 `User` 表里按 `openid` 查找；没有就插入一行。不按用户分表，不保存 `session_key`。
5. 用现有 `signToken({ userId })` 签发 JWT，有效期仍为 7 天。
6. 客户端用现有 `setToken` 写入 `douding_auth_token`（并兼容旧键 `token`）。之后业务请求自动带 `Authorization: Bearer <token>`。
7. 启动阶段的这次登录会挡住其他业务请求，避免训练接口先于登录发出。登录失败不清除已经存在的 token。
8. 没有配 AppSecret、或微信拒绝时，不编造 openid。健身页在本地仍然没有 token 时，继续调用 `dev-login`。

不从个人中心占位页进入。占位页本阶段不改。

## 接口

### `POST /api/auth/wechat-login`

请求体：

```ts
interface WechatLoginRequest {
  code: string
}
```

成功时 HTTP 200：

```ts
interface WechatLoginSuccess {
  code: 200
  message: '微信登录成功'
  data: {
    token: string
    user: {
      id: string
      openid: string
      nickname: string | null
      avatarUrl: string | null
      gender: number | null
      height: number | null
      weight: number | null
      targetWeight: number | null
    }
  }
}
```

新用户的昵称是 `微信用户`。再次登录不覆盖已有昵称、头像和身体数据。响应里没有 `session_key`。

失败时 HTTP 状态与 `code` 相同，`message` 说明原因：

| 情况 | HTTP | message |
| :--- | :--- | :--- |
| 没有 `code`，或 `code` 是空白 | 400 | `缺少微信 code 参数` |
| 未配置 `WX_APPID` 或 `WX_SECRET` | 503 | `未配置微信 AppID 或 AppSecret（环境变量 WX_APPID、WX_SECRET）。本地没有密钥时请调用 /api/auth/dev-login` |
| 微信返回 `errcode`（含 AppSecret 错误 40125、code 无效 40029） | 400 | `微信拒绝了这次登录（{errcode}）：{errmsg}` |
| 微信没有返回 `openid` | 400 | `微信没有返回 openid，登录未完成` |
| 微信返回的不是对象 | 400 | `微信返回了无法识别的登录结果` |
| 微信网络失败、非 200、或响应不是 JSON | 502 | `微信登录服务暂不可用，请稍后再试` |

这些失败都不创建用户，也不返回假 openid。响应和日志都不包含 AppSecret。不再返回 501。

`session_key` 只存在于微信当次响应的内存解析里，不入库、不回给小程序、不写日志。

### `POST /api/auth/dev-login`

行为不变。本地没有 AppSecret 时用它换测试用户 `test-user-001` 的 JWT。

## 环境变量

只从进程环境读取，不写进仓库，不提交 `.env`：

| 变量 | 作用 |
| :--- | :--- |
| `WX_APPID` | 小程序 AppID。示例文件里是已公开的 `wx606fc804e012e441` |
| `WX_SECRET` | 小程序 AppSecret。只放在本机 `server/.env`，由微信公众平台发放 |
| `JWT_SECRET` | 签发 JWT。未设置时服务沿用现有开发默认值 |
| `DATABASE_URL` | Prisma SQLite，例如 `file:./dev.db` |

## 数据

不改 `schema.prisma`。用户仍是 `User` 一行，`openid` 唯一。

## 明确不做什么

- 不改饮食、AI 教练、个人中心占位页，也不做手机号、头像昵称授权。
- 不把 `dev-login` 当成线上登录，也不在微信登录失败时自动伪装成测试用户。
- 不把 AppSecret、`session_key`、token 打进日志或提交进 git。
- 不改 `/api/workout` 的路径和字段。

## 怎样算完成

- 纯函数：code2Session 结果变成用户种子或明确错误；用户 id 签出的 JWT 能解回同一个 `userId`；文案不带密钥。
- `POST /api/auth/wechat-login` 按上表返回。成功时 data 里有 JWT。
- 小程序启动会拿 `code` 调该接口，成功后把 token 存进 `douding_auth_token`。
- `pnpm type-check`、`pnpm exec tsc --noEmit`、`pnpm exec vitest run` 通过。

## 本地试一次

在 `server/`：

```bash
cp .env.example .env
```

把 `.env` 里的 `WX_SECRET` 换成微信公众平台该小程序的 AppSecret。不要提交 `.env`。没有数据库时再执行 `pnpm prisma:migrate` 和 `pnpm prisma:seed`。然后 `pnpm dev`。

用微信开发者工具打开 `client` 的微信小程序预览。启动后会自己 `uni.login` 并请求登录接口。成功时本地存储出现 `douding_auth_token`。

还没填 AppSecret 时，可以直接看错误：

```bash
curl -s -X POST http://127.0.0.1:3000/api/auth/wechat-login \
  -H 'Content-Type: application/json' \
  -d '{"code":"local-check"}'
```

应得到 503 和上面的未配置说明，而不是 501。本地继续用：

```bash
curl -s -X POST http://127.0.0.1:3000/api/auth/dev-login \
  -H 'Content-Type: application/json' \
  -d '{"userId":"test-user-001"}'
```
