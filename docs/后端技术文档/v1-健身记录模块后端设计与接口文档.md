## 一、 模块职责与架构概览

健身记录模块作为豆丁健身的核心业务模块，主要负责：
1. **月度日历打卡数据聚合**：按月份极速查询用户的打卡天数与简字部位（如“胸”、“肩”），为日历网格提供高吞吐的轻量级摘要数据。
2. **单日训练详情查询**：查询某天的完整训练时长、主练部位、动作组数明细（动作名、重量、次数）。
3. **打卡数据录入与幂等更新 (Upsert)**：支持用户保存/修改某一天的训练记录，并自动级联动作明细。
4. **首页本周打卡联动**：提供周训练频次计算，驱动首页卡片实时高亮。

## 二、 数据库模型设计 (Prisma Schema)

在 [`server/prisma/schema.prisma`](file:///d:/douding-fitness/server/prisma/schema.prisma) 中，与健身打卡相关的核心模型如下：

```prisma
// 健身打卡记录主表
model WorkoutRecord {
  id          String         @id @default(uuid())
  userId      String         // 归属用户 ID
  user        User           @relation(fields: [userId], references: [id], onDelete: Cascade)
  date        String         // 训练日期，统一格式: "YYYY-MM-DD" (例如 "2026-10-08")
  duration    Int            @default(0) // 训练总时长(分钟)，例如 60
  bodyParts   String         // 训练部位: 如 "肩部 & 手臂"
  notes       String?        // 训练心得或备注
  createdAt   DateTime       @default(now())
  updatedAt   DateTime       @updatedAt

  exercises   ExerciseItem[] // 关联的具体动作与组数明细

  @@index([userId, date])   // 联合索引，加速按用户和日期范围极速查询
}

// 具体训练动作与组数明细表
model ExerciseItem {
  id              String        @id @default(uuid())
  workoutRecordId String
  workoutRecord   WorkoutRecord @relation(fields: [workoutRecordId], references: [id], onDelete: Cascade)
  actionName      String        // 动作名: 例如 "哑铃推举"
  sets            Int           // 组数序号: 1, 2, 3...
  weight          Float         // 负重重量 (kg)
  reps            Int           // 每组重复次数
  createdAt       DateTime      @default(now())

  @@index([workoutRecordId])
}
```

### 字段优化说明：
- `date` 字段采用标准 `YYYY-MM-DD` 字符串存储，不仅规避了不同时区转换的隐患，而且极大方便了前后端日期比对与 `LIKE "2026-10-%"` 的月份前缀查询。
- `@@index([userId, date])` 确保即使有数万条打卡记录，用户拉取当月打卡依然可以在 5ms 以内瞬间响应。

## 四、 RESTful API 接口规范

统一前缀：`/api/workout`  
统一鉴权：请求头需携带 `Authorization: Bearer <jwt_token>`（当前静态阶段可允许 Mock 用户 ID 兜底）。

### 4.1 获取指定月份的训练打卡摘要（用于日历渲染）

* **请求路径**：`GET /api/workout/month`
* **Query 参数**：
  * `year`: 年份（如 `2026`，必填）
  * `month`: 月份（如 `10`，必填）
* **响应格式**：
```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "date": "2026-10-01",
      "bodyPartBadge": "胸",
      "bodyParts": "胸部塑形",
      "duration": 45
    },
    {
      "date": "2026-10-02",
      "bodyPartBadge": "肩",
      "bodyParts": "肩部 & 手臂",
      "duration": 60
    },
    {
      "date": "2026-10-04",
      "bodyPartBadge": "背",
      "bodyParts": "背部强化",
      "duration": 50
    }
  ]
}
```

* **请求路径**：`GET /api/workout/day`
* **Query 参数**：

### 4.3 提交/保存单日训练打卡（支持新增与更新）

* **请求路径**：`POST /api/workout`
* **请求体 (Body)**：
```json
{
  "date": "2026-10-08",
  "duration": 60,
  "bodyParts": "肩部 & 手臂",
  "notes": "泵感十足",
  "exercises": [
    {
      "actionName": "哑铃推举",
      "sets": 4,
      "weight": 20.0,
      "reps": 10
    }
  ]
}
```
* **处理逻辑**：
  - 检查该用户在 `date` 当天是否已有记录：
    - 若已有记录：更新时长、部位与动作明细（Upsert 逻辑）。
    - 若无记录：新建记录与动作。
* **响应格式**：
```json
{
  "code": 200,
  "message": "打卡记录保存成功",
  "data": {
    "id": "uuid-record-1",
    "date": "2026-10-08",
    "duration": 60,
    "bodyParts": "肩部 & 手臂"
  }
}
```

### 4.4 删除指定训练记录

* **请求路径**：`DELETE /api/workout/:id`
* **响应格式**：
```json
{
  "code": 200,
  "message": "删除成功",
  "data": true
}
```

## 五、 后端分层代码架构与实现指引

代码严格遵守三层架构原则，目录结构规划如下：

```text
server/src/
├── controllers/
│   └── workout.controller.ts     # 参数校验、HTTP 响应封装
├── services/
│   └── workout.service.ts        # Prisma 数据交互与业务逻辑（计算简字徽章、汇总周频次）
├── routes/
│   ├── index.ts                  # 路由聚合
│   └── workout.route.ts          # /api/workout 路由定义
└── middlewares/
    ├── auth.middleware.ts        # JWT 身份解析中间件
    └── error.middleware.ts       # 全局异常捕获
```

### 5.1 业务核心：部位简字提取逻辑 (`service`)
在返回月度摘要时，服务层自动将 `bodyParts` 提取为单个精炼汉字：
```typescript
function extractBadge(bodyParts: string): string {
  if (bodyParts.includes('胸')) return '胸';
  if (bodyParts.includes('背')) return '背';
  if (bodyParts.includes('腿')) return '腿';
  if (bodyParts.includes('肩')) return '肩';
  if (bodyParts.includes('臂') || bodyParts.includes('二头') || bodyParts.includes('三头')) return '臂';
  if (bodyParts.includes('腰') || bodyParts.includes('核心')) return '腰';
  if (bodyParts.includes('有氧')) return '跑';
  return bodyParts.charAt(0) || '练';
}
```

## 六、 异常处理与安全规范

1. **用户数据隔离**：所有增删查改必须强制携带 `userId = req.user.id`，严禁越权查看或篡改他人打卡。
2. **入参防御性校验**：
   - `date` 必须严格匹配 `^\d{4}-\d{2}-\d{2}$` 格式。
   - `duration` 限制在 `1 ~ 600` 分钟之间，避免恶意非法参数。
3. **级联安全删除**：Prisma 模型配置了 `onDelete: Cascade`，删除打卡记录时自动清理下属的 `ExerciseItem` 动作明细，杜绝孤儿数据。
