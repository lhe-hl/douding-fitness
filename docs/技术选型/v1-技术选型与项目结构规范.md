## 一、 项目背景与核心目标

### 1.1 业务需求
- **健身打卡**：日历视图直观展示打卡记录，记录训练部位（胸、背、腿、肩、手臂、核心/有氧）、训练动作、组数、重量（kg）、次数（次）及训练时长。
- **减脂饮食记录**：按餐次（早餐、午餐、晚餐、加餐）录入食物名称、预估热量（kcal）、三大宏量营养素估算，支持拍摄减脂餐照片存证。
- **AI 智能教练**：结合当日运动消耗与饮食摄入，计算当日能量缺口，利用大模型提供智能减脂改进建议；同时支持流式对话问答（动作指导、平台期突破）。

- **微信小程序 AppID**：`wx606fc804e012e441`
- **运行环境**：Node.js `v24.12.0` / npm `11.14.1` / pnpm `10.33.1`

## 二、 前端技术栈选型解析 (Client)

### 2.1 为什么必须使用 uni-app？
1. **浏览器 Vue 无法直接跑在微信中**：微信小程序底层运行在定制的 JavaScriptCore / V8 视图渲染双线程架构中，没有 DOM 和 BOM API（没有 `document`、`window`、`div` 等）。
2. **原生小程序语法体验差**：微信原生语法（WXML/WXSS/WJS）缺少现代工程化模块支持，TypeScript 提示较弱，不能充分利用 Vue 3 的 Composition API 生态。
3. **uni-app 的核心价值**：
   - 允许你使用标准 **Vue 3 + TypeScript** 语法编写界面。
   - 底层由 **Vite** 驱动，实时将 `.vue` 单文件组件编译为微信小程序原生代码（WXML/WXSS/JS/JSON）。
   - 未来如果需要上线 App 或发布为 Web H5，无需重写，一套代码多端编译。

### 2.2 前端技术清单
| 维度 | 选型 | 选用原因 |
| :--- | :--- | :--- |
| **基础语言** | **TypeScript 5.x** | 提供完整的类型约束与接口提示，大幅降低运行时排错成本。 |
| **UI 框架** | **Vue 3 (Composition API / `<script setup>`)** | 业界主流前端标准，逻辑复用性高，响应式性能优异。 |
| **工程构建** | **Vite 5.x + @dcloudio/vite-plugin-uni** | 秒级热更新（HMR），编译速度极快。 |
| **移动端组件库** | **Wot Design Uni (推荐)** | 专为 Vue 3 + uni-app 打造的现代化移动组件库，样式美观，开箱支持暗黑模式，原生 TS 支持好。 |
| **状态管理** | **Pinia** | Vue 官方推荐状态管理，轻量且类型安全，用于管理用户登录态、打卡临时草稿。 |
| **网络请求** | **封装 uni.request (支持 Promise 与 TS 类型)** | 自定义请求拦截（自动携带 JWT Token）、响应拦截（统一错误弹窗）。 |

## 三、 后端技术栈选型解析 (Server)

在 Node.js + TypeScript 生态中，主流后端框架主要有 **Express**、**NestJS** 和 **Fastify**。以下是针对本项目的选型权衡：

### 3.1 框架深度对比

| 框架 | 学习曲线 | 架构特点 | 优缺点分析 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **Express.js (TypeScript)** | **入门极快** (平缓) | 轻量极简，中间件机制灵活 | **优点**：代码直观透明，社区资料极其丰富，排错简单，零过度设计。<br>**缺点**：需要手动规范三层分层（Controller-Service-Repository）。 | **全栈个人项目首选**、快速验证 MVP、希望清楚看到每一行代码执行细节。 |
| **NestJS** | **较陡峭** (偏重) | 企业级 OOP/IoC/DI 依赖注入架构（风格接近 Java Spring Boot） | **优点**：规范高度一致，架构天然严密，模块化解耦极佳。<br>**缺点**：概念多（Module/Controller/Service/Guard/Pipe/Decorator），初学者样板代码多，上手较重。 | 中大型团队协作、企业级复杂业务、有 Spring/Angular 经验的开发者。 |
| **Fastify** | **中等** | 类似 Express 但性能极致 | **优点**：吞吐量极高，原生支持 JSON Schema 校验。<br>**缺点**：生态插件没有 Express 广泛。 | 超高并发接口场景。 |

### 3.2 v1 最终推荐决策
- **推荐方案：Express.js + TypeScript + 经典三层架构 (Controller / Service / Prisma)**
  - **理由**：作为个人学习和全栈实践项目，Express 结合 TypeScript 既能保证强类型和清晰的分层代码结构，又不会让你陷入 NestJS 繁琐的依赖注入与装饰器配置泥潭中，能以最快速度完成业务闭环。
- *(备选)*：如果你希望借此项目系统掌握**企业级大型项目架构规范**并对标大厂 Spring 风格，也可以选择 **NestJS**。

## 四、 数据库与数据持久化方案

### 4.1 ORM 框架：Prisma ORM
- **为什么选 Prisma**：
  - **声明式建模**：使用直观的 `schema.prisma` 文件定义数据表与关联关系。
  - **类型全自动化**：运行 `npx prisma generate` 即可自动生成完整的 TypeScript 实体类型，前后端调用均有代码补全。
  - **自带可视化 GUI**：内置 `npx prisma studio`，在浏览器中即可如同 Excel 一般直接查看与编辑数据库。

### 4.2 本地数据库：SQLite (开发阶段) -> MySQL (生产阶段)
- **开发阶段（SQLite）**：
  - 本地单文件（如 `dev.db`），**无需在电脑上下载安装 MySQL、配置 root 密码或开启服务**，开箱即用。
  - 避免环境冲突，换任何电脑克隆代码即可直接跑。
- **生产阶段（MySQL / PostgreSQL）**：
  - 由于使用 Prisma，在切换为正式服务器云数据库时，仅需将 `schema.prisma` 中的 `provider = "sqlite"` 改为 `provider = "mysql"`，业务代码无需修改一行。

## 七、 各模块职责与规范说明

### 7.1 核心数据表设计 (Prisma Schema 预览)
1. **User (用户表)**：
   - 包含 `id`, `openid` (微信唯一标识), `nickname`, `avatarUrl`, `gender`, `height` (cm), `weight` (kg), `targetWeight`, `createTime`。
2. **WorkoutRecord (健身打卡主表)**：
   - 包含 `id`, `userId`, `date` (YYYY-MM-DD), `bodyParts` (以逗号分隔的肌群标签), `duration` (分钟), `notes` (心得备注)。
3. **ExerciseItem (训练动作明细表)**：
   - 包含 `id`, `workoutRecordId`, `actionName` (如“卧推”), `sets` (第几组), `reps` (次数), `weight` (公斤)。
4. **DietRecord (饮食记录表)**：
   - 包含 `id`, `userId`, `date` (YYYY-MM-DD), `mealType` (BREAKFAST, LUNCH, DINNER, SNACK), `foodName`, `calories` (kcal), `protein`, `carbs`, `fat`, `photoUrl`。

### 7.2 微信鉴权流转规范
```text
小程序端 (uni.login)
     │
     ▼ 获取临时 js_code
小程序端发起请求 POST /api/v1/auth/wechat-login { code }
     │
     ▼
后端收到 code，携带 AppID + AppSecret 请求微信接口:
https://api.weixin.qq.com/sns/jscode2session
     │
     ▼ 微信返回 openid & session_key
后端查询/创建 User 记录，签发自定义 JWT Token
     │
     ▼ 返回 { token, userInfo } 给小程序
小程序端将 Token 存入本地 Storage (uni.setStorageSync)
后续所有业务接口均在 Header 携带: Authorization: Bearer <token>
```

## 八、 全流程开发、调试、预览与发布闭环

### 8.1 本地开发与联调模式
1. **启动后端服务**：
   - 在 `server` 目录运行 `pnpm dev`，后端启动在 `http://localhost:3000`。
2. **启动前端开发监听**：
   - 在 `client` 目录运行 `pnpm dev:mp-weixin`。
   - Vite 启动监听并将代码持续输出到 `client/dist/dev/mp-weixin`。
3. **微信开发者工具预览**：
   - 首次在微信开发者工具导入 `d:\douding-fitness\client\dist\dev\mp-weixin`。
   - 设置勾选 **“不校验合法域名、web-view、TLS版本以及HTTPS证书”**。
   - 在 VS Code 中编辑任何 `.vue` 页面，保存后开发者工具中的手机模拟器将自动热刷新。

### 8.2 真机扫码与体验版发布
1. **真机预览**：点击微信开发者工具顶部的 **“预览”** 按钮生成二维码，用手机微信扫码测试真实体验。
2. **多人体验版**：点击开发者工具顶部的 **“上传”** 按钮，在公众平台将该上传版本设为“体验版”，添加测试成员即可共同测试。

### 8.3 正式提审与发布
1. **生产打包**：运行 `pnpm build:mp-weixin`，生成体积经过压缩最小化的 `dist/build/mp-weixin` 代码包。
2. **部署后端**：将 Node.js 后端部署至轻量服务器或云托管，配置域名 SSL 证书（HTTPS），在微信后台配置服务器域名白名单。
3. **提交审核**：在微信公众平台点击提交官方审核，审核通过后一键全量发布。
